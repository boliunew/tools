# 家庭网络入门

家里的网络看着就是「一个路由器 + 一堆设备」，但主机要长期在线、手机在外面也要连得回来，就得弄明白几件事：**设备的地址怎么来**、**名字怎么变成地址**、**外面的流量怎么进来**。

## IP 地址：局域网和公网

每台联网设备都有一个 IP 地址，相当于门牌号。家里其实有两套门牌：

| 类型 | 长什么样 | 谁能看到 | 谁分配 |
|---|---|---|---|
| 局域网（私有）IP | `192.168.x.x`、`10.x.x.x`、`172.16–31.x.x` | 只有家里的设备 | 你的路由器 |
| 公网 IP | 其它地址，比如 `73.x.x.x` | 全世界 | 宽带运营商 |
| Tailscale IP | `100.x.x.x` | 只有你 Tailscale 网络里的设备 | Tailscale |

家里所有设备共用**一个**公网 IP（就是路由器拿到的那个）。在搜索引擎搜「what is my ip」看到的就是它。电脑上 `ipconfig` 看到的 `192.168.1.23` 则是局域网地址，出了家门就没用了。

> 有的运营商连公网 IP 都不给你，而是让很多户共用一个（叫 CGNAT，地址常在 `100.64.x.x` 段）。这种情况下端口转发根本做不了，这也是 Tailscale 这类工具好用的原因之一。

IPv6 地址很长（像 `2601:...`），理论上每台设备都能有公网地址。家里大多是 IPv4 和 IPv6 同时在跑，入门阶段先把 IPv4 搞懂就够了。

## 路由器和 NAT

家用「路由器」其实一个盒子干了好几件事：路由、交换机（那几个网口）、WiFi、DHCP、防火墙。

**NAT**（网络地址转换）是它最关键的工作：家里设备往外发请求时，路由器把源地址换成公网 IP，回来的数据再按记录送回对应设备。结果就是：

- 家里设备**往外**访问随便连；
- 外面的人**主动往里**连，路由器不知道该给谁，直接丢掉。

这其实是一层天然的保护。迷你主机放在家里，默认外面是访问不到的。

## DHCP 和固定 IP

设备连上网时，路由器的 **DHCP** 服务会自动发一个局域网 IP，有效期（租约）一般一天左右，到期可能换一个。手机、电脑无所谓，但**主机地址老变就麻烦了**：书签、SSH 配置、端口转发都会失效。

两种固定办法：

| 方法 | 在哪设置 | 优点 |
|---|---|---|
| **DHCP 保留**（推荐） | 路由器后台，把主机的 MAC 地址绑定到一个 IP | 主机不用改任何配置，统一在路由器管理 |
| 主机上写死静态 IP | Ubuntu 的 netplan 配置 | 不依赖路由器，但要避开 DHCP 地址池，换路由器容易冲突 |

DHCP 保留在路由器后台一般叫「地址保留」「静态租约」「DHCP Reservation」。如果非要在 Ubuntu Server 上写死，大致是这样（网卡名用 `ip a` 查，文件在 `/etc/netplan/` 下）：

```yaml
network:
  version: 2
  ethernets:
    enp1s0:
      dhcp4: false
      addresses: [192.168.1.50/24]
      routes:
        - to: default
          via: 192.168.1.1
      nameservers:
        addresses: [1.1.1.1, 8.8.8.8]
```

改完用 `sudo netplan try`，它会在一段时间内等你确认，连不上就自动回滚，远程操作时很救命。

> 安卓手机（包括 S23 Ultra）默认每个 WiFi 用一个**随机 MAC 地址**。要给手机做 DHCP 保留，得在该 WiFi 的详细设置里把「MAC 地址类型」改成「手机 MAC」。主机用网线就没这个问题。

## DNS：把名字翻译成地址

你输入 `example.com`，电脑先去问 **DNS 服务器**「这个名字的 IP 是多少」，拿到地址才去连。DNS 出问题的典型症状是：**能 ping 通 IP，但网页打不开**。

默认 DNS 由运营商提供，经路由器转发。也可以换成公共 DNS：

| 地址 | 提供方 | 特点 |
|---|---|---|
| `1.1.1.1` / `1.0.0.1` | Cloudflare | 速度快，注重隐私 |
| `8.8.8.8` / `8.8.4.4` | Google | 老牌，稳定 |
| `9.9.9.9` | Quad9 | 自带恶意域名拦截 |

在路由器里改 DNS，全家设备都生效；只在某台电脑上改，只影响它自己。

**Pi-hole** 是可以装在家里主机上的 DNS 服务：把全家的 DNS 指向它，它会把广告和跟踪域名直接拦掉，还能看到每台设备都在查什么。迷你主机跑它几乎不占资源，但它一停全家都上不了网，装之前要想好备用 DNS。

Tailscale 还有个 **MagicDNS**：开启后可以直接用机器名（比如 `minipc`）访问主机，不用记 `100.x` 地址。

## 端口和端口转发

一个 IP 上可以同时跑很多服务，用**端口号**区分：

| 端口 | 常见服务 |
|---|---|
| 22 | SSH 远程登录 |
| 80 / 443 | 网页 HTTP / HTTPS |
| 53 | DNS |
| 8000、8080 等 | 自己写的程序常用 |

**端口转发**就是告诉路由器：「外面来访问公网 IP 的 443 端口，转给 `192.168.1.50` 的 443」。这样外面就能访问家里主机了，但代价是：

- 全网的扫描器都会来敲这个端口，SSH 每天被暴力猜密码几千次很常见；
- 主机上的程序有漏洞，就是直接暴露在公网；
- 公网 IP 会变，还得配动态域名（DDNS）；遇到 CGNAT 根本做不了。

**Tailscale 为什么不用开端口：** 每台装了 Tailscale 的设备都主动**往外**连协调服务器，再用 NAT 穿透技术在设备之间直接打通加密隧道（基于 WireGuard）。打不通时走 Tailscale 的中继服务器。全程都是「往外连」，所以路由器上一个端口都不用开，外人也看不到你的服务。

| 场景 | 建议 |
|---|---|
| 只有自己用（手机、Windows 电脑访问主机） | Tailscale，零端口 |
| 网站要让公众访问 | Tailscale Funnel 或 Cloudflare Tunnel，同样不用开端口 |
| 非开端口不可 | 只开 443，SSH 禁止密码登录，装 fail2ban |

## WiFi：2.4 / 5 / 6 GHz

| 频段 | 速度 | 穿墙/距离 | 说明 |
|---|---|---|---|
| 2.4 GHz | 慢 | 最好 | 邻居多、微波炉、蓝牙都挤在这里，智能家居设备常只支持它 |
| 5 GHz | 快 | 一般 | 日常主力，隔一两堵墙就明显变弱 |
| 6 GHz | 最快、最干净 | 最差 | 需要 WiFi 6E 或 WiFi 7 的路由器和设备，S23 Ultra 支持 6E |

WiFi 6（802.11ax）、WiFi 7（802.11be）是代际名称，和频段不是一回事。路由器把几个频段合成一个名字时，设备会自动挑；遇到智能设备配网失败，可以临时单独开一个 2.4 GHz 网络。

## 网线：Cat5e 还是 Cat6

**主机一定要插网线。** 有线延迟低、不掉线，WiFi 再快也比不上稳定。

| 类别 | 速度 | 说明 |
|---|---|---|
| Cat5e | 1 Gbps（100 米内），短距离多半也能跑 2.5 Gbps | 家用完全够 |
| Cat6 | 1 Gbps；10 Gbps 约 55 米内 | 新买就买这个，价格差不多 |
| Cat6a | 10 Gbps（100 米内） | 更粗更硬，确定要万兆再考虑 |
| Cat7 / Cat8 | — | 家用没必要，很多是营销 |

实际速度还受**网口**限制：路由器和主机都是千兆口，换什么线都是千兆。

## Mesh 组网

房子大、一个路由器覆盖不过来时，用 **Mesh**：几个节点组成一个网络，同一个 WiFi 名字，手机走动时自动切换。

- 节点之间能**用网线连（有线回程）**最好，性能接近单个路由器；
- 无线回程会占用一部分带宽，离主路由越远越慢；
- 比起 WiFi 中继器（扩展器），Mesh 切换更顺滑，不会出现两个网络名。

## 常用排查命令

| 想知道什么 | Windows | Ubuntu |
|---|---|---|
| 本机 IP | `ipconfig`（详细：`ipconfig /all`） | `ip a` |
| 网关（路由器）地址 | `ipconfig` 里的「默认网关」 | `ip route` |
| 能不能通 | `ping 192.168.1.1` | `ping -c 4 192.168.1.1` |
| 域名解析 | `nslookup example.com` | `nslookup example.com` 或 `resolvectl query example.com` |
| 卡在哪一跳 | `tracert example.com` | `traceroute example.com`（需 `sudo apt install traceroute`）或自带的 `tracepath` |
| 某个端口通不通 | `Test-NetConnection 主机 -Port 443`（PowerShell） | `nc -zv 主机 443` |
| 本机在监听哪些端口 | `netstat -ano` | `ss -tlnp` |
| 清 DNS 缓存 | `ipconfig /flushdns` | `resolvectl flush-caches` |
| Tailscale 状态 | `tailscale status` | `tailscale status`、`tailscale ping minipc` |

**排查顺序**，从近到远：

1. `ping` 路由器 —— 不通就是本机网线 / WiFi 问题；
2. `ping 1.1.1.1` —— 不通就是路由器或运营商出了问题；
3. `ping example.com` —— IP 通、域名不通就是 DNS 问题；
4. `tracert` / `traceroute` 看在哪一跳开始超时。

**测速：** 外网速度用 speedtest.net 或 fast.com；家里两台设备之间的速度用 `iperf3`（主机上 `iperf3 -s`，电脑上 `iperf3 -c 主机IP`），能看出是 WiFi 慢还是宽带慢。测速最好用网线，WiFi 测出来的数字受距离和干扰影响很大。
